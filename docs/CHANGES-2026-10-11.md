## What changes on the dashboards

- **Every row is reprocessed once** on the next sync (the rule version went from 2
  to 4). That is normal and only happens once.
- **More rows land in the review queue.** New reasons: a patient identifier in
  *any* column (not only name and notes), an expiration date before the item
  reached the warehouse, or more than 10 years away. A row someone already marked
  as reviewed goes back to the queue if it gains a new reason.
- **Photos are hidden** for any row where *any* text column (name, notes, General,
  lot number, manufacturer, category, review, box label) had something to redact.
- **`dash_supplies`**: `"Quantity"` is now always the number we understood
  (`"20 (pens)"` shows `20`), and `"Date of Expiration"` is `YYYY-MM-DD` whenever it
  could be understood (`"01/2024"` becomes a real date). Otherwise the original
  text is shown. Before, both showed the raw sheet text, which dashboards misread.
- **`dash_items`** has a new last column `lot_number` (redacted).
- **New view `dash_sync_status`**: one row with when the data was last refreshed,
  whether the latest run worked, whether a safety guard stopped it
  (`last_run_refused`), the warning count and the number of active items. A run
  that could not read the sheet or was stopped by a guard is never counted as a
  success.
- Every text column in every dashboard view is redacted now, not only names and
  notes. Redaction is done in the database, so it applies to any dashboard.

## Privacy: what is redacted now

Patient IDs, research-subject IDs (also with spaces, other dash characters or
look-alike letters), MRNs, dates of birth (numeric and written out, "born on"),
SSN-shaped numbers, emails, US phone numbers, and patient names written after
"Patient" or "Pt." (with a colon or dash: the next few words; without a label: up to
three capitalised words, with accented letters, apostrophes, particles like "van
der" and non-Latin scripts). Invisible characters and full-width letters are
removed or folded before matching. Ordinary product names that start with
"Patient" ("Patient Gait Belt", "Patient Return Electrode") are left alone, using a
list of supply words; a product word that is not on the list will be redacted
(over-redacting is the safe side). A test runs over 500 such names.

**Known gaps** (no keyword to find them by): "Name: John Smith" and "Mr. Smith
patient". These rely on the review queue and on photo hiding. Lowercase "pt"
without a period ("pt smith") is deliberately not treated as a name because "pt" is
also a unit (12 pt font) or a pint.

## New and improved commands

- `python -m b4p doctor`: read-only setup check (database host and name without
  password, connectivity, tables, views, functions, credentials present, last sync).
- `python -m b4p check --details [--limit N]`: lists the exact sheet rows, boxes and
  pallets behind each warning. Names are redacted.
- `python -m b4p check --aliases`: lists spellings that no alias covers, with
  suggested rows (spellings that may be two companies are labelled "needs a human").
- `python -m b4p status`: shows requests by status, the last sync result, the last
  good sync, and how many checks warn.
- On an old database the commands now say "run `b4p init`" instead of crashing.

## Sync safety and cleanup

- A sync stopped by a guard (wrong tab, too many items missing) is recorded as
  refused. It is excluded from "last success" so a freshness banner cannot stay
  green on frozen data.
- Repeated column headers in the sheet: the first column wins in both ways of
  reading the sheet, with a warning; a leading byte-order mark no longer breaks
  the header check.
- **"Days in Warehouse" no longer makes every row look changed each day.** The sheet's
  formula grows by one daily; it now only counts as an edit when it no longer fits
  the warehouse date we stored. A normal day's sync updates nothing (20,000 rows used to
  take about a minute locally, far longer over the network). `dash_supplies` shows
  this column computed from the stored date, so it stays current between syncs.
- Negative prices are ignored. Ambiguous cells (quantity "5-10" or "1e3", price
  "1.234") are still read but add a warning.
- Test fixtures were scrubbed of real patient identifiers (including the Lot Number
  column and the compressed supplies file), and a test now scans every fixture.
